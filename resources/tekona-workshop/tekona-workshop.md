# 手児奈にプロポーズ！ AIと演じる参加型紙芝居

〜 国府台・真間の伝承「手児奈」を、みんなで新しく語り直す（40分）〜

# 0. この時間の内容

昔、現在の市川市真間に「手児奈（てこな）」という娘がいました。
その美しさは評判になり、里の若者、国府の役人、都の貴族などが次々に求婚に訪れます。

この時間には、参加者がそれぞれ**求婚者を1人ずつ**デザインし、全員の求婚者が登場する紙芝居を作ります。

1. 時代背景を調べ、自分の求婚者（身分・外見・ポーズ・セリフ）を考えます。
2. 生成AI（Copilot）で、求婚者の絵を3枚作ります。
3. ポーズ認識AI（Teachable Machine）に、自分の3つのポーズを学習させます。
4. 絵・セリフ・モデルのリンクを掲示板に提出すると、スタッフが共有の紙芝居に組み込みます。
5. 最後に、全員の求婚者が登場する紙芝居を上演します。手児奈は、全員の求婚を断ります。

> ⭐️ ポーズの写真は、自分のPCでAIに学習させるためだけに使います。写真は掲示板に提出しません。ワークショップの終了後に削除します。

## 求婚者の決まり（全員共通）

**構図**：どの求婚者も、舞台の**上手**（かみて：画面の**右側**）に立ち、**下手**（しもて：画面の**左側**）にいる手児奈に求婚します。
そのため、求婚者の絵は、人物が画面の左を向くように描きます。

```text
 下手（画面の左）                    上手（画面の右）
   手児奈        ←  求婚する  ←      あなたの求婚者
```

**3枚の絵と3つのポーズ**：求婚者ごとに、次の3つを同じ名前でそろえます。絵のファイル名も、ポーズ認識AIのクラス名（ラベル）も、この名前にします。

| 名前（半角小文字） | 絵（ファイル名） | ポーズ（Teachable Machineのクラス） | 紙芝居で使う場面 |
| --- | --- | --- | --- |
| `stand` | `stand.png`：まっすぐ立っている姿 | 気をつけの姿勢 | 登場するとき |
| `kime` | `kime.png`：求婚の決めポーズ | 決めポーズ | 「カメラの前で、求婚のポーズを決めよう！」 |
| `rejected` | `rejected.png`：断られて落胆したポーズ | 落胆のポーズ | 「断られた……。がっかりのポーズ！」 |

紙芝居の流れは全員共通です：**登場（`stand`）→ 求婚のポーズ（`kime`）→ 求婚の言葉 → 手児奈が断る → 落胆のポーズ（`rejected`）→ 一言**。

## 席番号

席番号（2桁）：**[　　]**　← 例：7番の人は`07`

掲示板への提出と、紙芝居で場面を並べる順番に使います。

## 使用するもの（PCのブラウザのタブ）

| タブ | 使用する場面 |
| --- | --- |
| Web検索 | 1. 調べる |
| Microsoft 365 Copilot | 2. 絵を作る |
| Teachable Machine（ポーズ） | 3. ポーズを学習させる |
| 掲示板 | 4. 提出する、5. 完成した紙芝居を見る |
| TurboWarp Plus Editor | （発展）自分の場面を試す |

配布資料フォルダの`copilot`には、次の2つの画像があります。

* `style-reference.png`：絵柄の見本。用意済みの求婚者の`stand`・`kime`・`rejected`を、左から順に並べたものです。
* `pose-draft.png`：棒人間を描くための白紙です。

# 1. 求婚者を考える（約7分）

スクリーンで、用意済みの3人の求婚者が登場する紙芝居を見たあと、4人目以降の求婚者として自分の求婚者を考えます。

## 1.1 時代背景を調べる

手児奈の物語は、1300年以上前のことと伝えられています。当時、真間に近い国府台には下総国の国府（国の役所）が置かれ、都から役人が派遣されていました。
次のうち1つを、Web検索で調べてみましょう。

* 当時の人は、どのような素材・形の服を着ていたか（検索例：「奈良時代 服装 庶民」）
* 身分によって、着用できる服の色に違いがあったか（検索例：「位色」）
* 真間の周辺には、どのような人々が暮らし、何をしていたか（検索例：「下総国府」「万葉集 手児奈」）

> ⚠️ 時代劇や漫画で見かける烏帽子やちょんまげは、もっと後の時代のものです。

## 1.2 求婚者カードを書く

| 項目 | ヒント | あなたのアイデア |
| --- | --- | --- |
| 1. 身分・職業 | 入江の漁師、機織りの名人、歌の上手な若者、郡司（地方の有力者）の息子 など | |
| 2. 人物像・表情 | 快活、まじめ、尊大、ロマンチスト など。どんな表情で求婚するか | |
| 3. 服装・髪型・装身具 | 布は麻か絹か、色は何色か、何を持っているか | |
| 4. 決めポーズ（`kime`） | 求婚するときのポーズ。1.3「ポーズの注意」を参照 | |
| 5. 落胆のポーズ（`rejected`） | 断られたときのポーズ。`kime`とも気をつけの姿勢とも明確に異なるもの | |
| 6. 求婚の言葉 | 「〇〇するから、妻になってください！」 | |
| 7. 手児奈の断りの言葉 | 穏やかに、しかしはっきりと | |
| 8. 断られたときの一言 | 求婚者の人柄が表れる一言 | |
| 9. 手児奈の心は揺れたか | 揺れた／揺れなかった | |

## 1.3 ポーズの注意

`stand`（気をつけの姿勢）・`kime`・`rejected`の3つを、AIが見分けられるようにします。

* **上半身だけで区別できる**ポーズにします。足だけが違うポーズや、しゃがむポーズは見分けられません。
* 3つのポーズが**互いに明確に異なる**ようにします。腕の高さ、肘の曲げ方、頭の向きを変えると、違いがはっきりします。
* **左右対称**のポーズ（両腕を同じように動かす）を勧めます。左右非対称のポーズは、カメラによって左右が反転して映り、正しく見分けられないことがあります。
* 誰でもすぐに再現でき、**数秒間静止できる**ポーズにします。
* 周りの人にぶつからない大きさにします。

## 1.4 棒人間を描く

`pose-draft.png`を右クリック →「ペイントで編集する」で開き、棒人間を**3人**、左から**`stand`・`kime`・`rejected`の順**に並べて描きます。
`draft.png`という名前で保存します。上手に描く必要はありません。腕の角度が分かれば十分です。

```text
   左            中央           右
 stand          kime        rejected
（気をつけ）  （決めポーズ）  （落胆のポーズ）
```

この順番は、絵の見本`style-reference.png`と、Copilotに作ってもらう絵の並びと同じです。

# 2. 生成AIで絵を作る（約4分＋待ち時間）

> ⚠️ Copilotで作成できる画像は、**1日に2枚程度**です。1枚目で`stand`・`kime`・`rejected`の**3人を1枚にまとめて**作成し、2枚目は失敗したときの予備にします。

1. Copilotの入力欄の「＋」→「画像とファイルのアップロード」で、絵柄の見本`style-reference.png`をアップロードします。
2. 同じ手順で、自分で描いた棒人間`draft.png`をアップロードします。
3. 次の文の〔　〕を求婚者カードの内容に書き換え、入力欄に貼り付けて送信します。

```text
次の人物の全身像を3つ、横一列に並べた画像を1枚作成してください。

人物：〔身分・職業〕。〔人物像・表情〕。〔服装・髪型・装身具〕。
時代は奈良時代、場所は下総国（現在の千葉県市川市）です。

絵柄：添付した1枚目の画像（見本）と同じ絵柄にしてください（太い輪郭線のない、シンプルな平面イラスト）。
姿勢：添付した2枚目の画像には、棒人間が3人並んでいます。左・中央・右の各全身像を、それぞれ同じ位置の棒人間と同じ姿勢にしてください。
・左：気をつけの姿勢で、まっすぐ立っている。
・中央：求婚の決めポーズ。〔決めポーズの説明〕
・右：求婚を断られて落胆したポーズ。〔落胆のポーズの説明〕

3つとも同じ人物・同じ大きさで、頭から足まで全身を入れ、互いに重ならないようにしてください。
3つとも、体と顔をやや画面の左に向けてください（画面の左にいる相手に話しかける向き）。
画像に文字は入れないでください。背景は #00FF00 の緑一色にしてください。
```

4. 画像の作成には数分かかります。**待っている間に、3. のポーズの学習を始めましょう。**

**うまくいかないとき**：2枚目で、文を少し変えて再度依頼します。2枚とも使えなかった場合は、スタッフに声をかけてください。
用意済みの人物の絵を使い、セリフとポーズだけを自分の求婚者のものにすることもできます。

# 3. AIに3つのポーズを学習させる（約10分）

Teachable Machineの「ポーズ」プロジェクトを使います。

1. クラスのラベルを、上から**`stand`**・**`kime`**・**`rejected`**にします。「Class 1」を`stand`、「Class 2」を`kime`に変更し、
   「＋ クラスを追加」で3つ目のクラスを作って`rejected`にします（半角小文字。この3つの名前は全員共通です）。
2. `stand`の「ウェブカメラ」を押し、カメラに**頭から腰まで**映る位置で気をつけの姿勢をとります。
   「長押しして録画」を押したまま、体を少しずつ動かしながら**30〜50枚**撮影します。
3. `kime`で、求婚の決めポーズを**30〜50枚**撮影します。腕の角度をわずかに変えたり、前後に半歩動いたりすると、よいサンプルになります。
4. `rejected`で、落胆のポーズを**30〜50枚**撮影します。
5. 関節の点と線（ボーン）が表示されていない写真や、他の人が写った写真は、ごみ箱のアイコンで削除します。
6. 「モデルをトレーニングする」を押し、完了を待ちます。
7. 「プレビュー」で3つのポーズを順にとり、それぞれ正しいクラスのグラフが伸びるか確認します。うまくいかなければ写真を追加して、再度トレーニングします。
8. 「モデルをエクスポートする」→「アップロード（共有可能なリンク）」→「モデルをアップロード」を押します。
   「クラウドモデルは最新です」と表示されたら、共有可能なリンクの右の「コピー」を押します。

**ブロック台本版で行う場合**：最初に「ファイルからプロジェクトを開く」で、配布資料フォルダの`seat-NN.tm`（NNは自分の席番号）を開きます。
クラス`stand`・`kime`・`rejected`は作成済みです。`kime`と`rejected`に入っている写真（スタッフによる仮のポーズ）をすべてごみ箱のアイコンで削除してから、
2.〜4.の撮影をします。8.では「モデルをアップロード」ではなく「**クラウドモデルを更新**」を押します。リンクは席ごとに決まっているので、提出は不要です。

## 考えてみよう

* 写真が少なすぎると、AIの判定はどうなるでしょうか。似た写真ばかりの場合はどうでしょうか。
* AIが学習したのは「写真」そのものでしょうか。それとも、写真から取り出された「体の形」でしょうか。

# 4. 仕上げて提出する（約6分）

## 4.1 絵を3枚に分け、背景を消す

1. Copilotが作成した画像を「保存」し、PNG形式でダウンロードします。
2. ペイントで開き、**左の人物**を四角形で選択して「トリミング」し、背景を消して**`stand.png`**として保存します。
3. 元の画像をもう一度開き、**中央の人物**を同じように処理して、**`kime.png`**として保存します。
4. 元の画像をもう一度開き、**右の人物**を同じように処理して、**`rejected.png`**として保存します。

ファイル名は、必ずこの3つにします（半角小文字、拡張子`.png`を残す）。背景の消し方は、スタッフがスクリーンで実演します。

## 4.2 掲示板に提出する

掲示板に、題名を「**NN 求婚者の名前**」（例：「07 入江の漁師」）として投稿します。

* 画像3枚：`stand.png`・`kime.png`・`rejected.png`
* 本文：次の形式で書きます。

```text
席番号：NN
作者の名前（紙芝居に表示してよい名前）：
求婚者の名前：
決めポーズの説明：
落胆のポーズの説明：
求婚の言葉：
手児奈の断りの言葉：
断られたときの一言：
手児奈の心は揺れたか（揺れた／揺れなかった）：
モデルのリンク：https://teachablemachine.withgoogle.com/models/……
```

絵が先に完成した場合は、絵とセリフを先に投稿し、モデルのリンクは後から同じ投稿への返信で提出してもかまいません。

## 4.3 （発展）自分の場面を試す

Scratchの経験がある人は、掲示板の「半完成品」（作業用SB3と台本`tekona.k4.yml`）を使い、自分の求婚者を自分のPCで試してみましょう。

1. TurboWarp Plus Editorで作業用SB3を開き、自分の席番号のスプライト`SuitorNN`（例：`Suitor07`）を選択します。
2. 「コスチューム」タブで、仮の絵`stand`を削除してから`stand.png`をアップロードします。`kime`・`rejected`も同様にします。
   コスチューム名が`stand`・`kime`・`rejected`になっていることを確認します。
3. `tekona.k4.yml`をメモ帳で開き、「★参加者」と書かれた雛形を参考に、自分の場面を`quarrel:`の前に追加します。
4. 緑の旗 → タイトルを閉じる → メニューの「開く」から`tekona.k4.yml`を選択し、自分のカメラでポーズを試します。

詳しい手順は、掲示板の「発展課題」の投稿にあります。試した台本は提出不要です（スタッフが提出物から組み込みます）。

# 5. 全員で上演する（約6分）

スタッフが、提出された求婚者を共有の紙芝居に組み込みます。
スクリーンで上演し、自分の求婚者の番が来たら、前方のカメラの前に立って、求婚のポーズ（`kime`）と落胆のポーズ（`rejected`）を決めてください。
組み込み済みの作品は掲示板にも投稿されるので、自分のPCで見直すこともできます。

# 6. まとめ（約3分）

## 本来の言い伝え

今回の紙芝居では、手児奈は「わたしの心は、わたしのもの」と自分の生き方を選び、男たちは争いをやめて入江に橋を架けました。
これは、言い伝えをもとに新たに作った**再話**です。

言い伝えでは、手児奈は自分をめぐって人々が争うことを悲しみ、夕日の入江に身を投げたとされています。
里の人々は手児奈を真間の井のそばに祀りました。現在も市川市真間には手児奈霊堂があり、
手児奈が水を汲んだという真間の井も残っています。手児奈の話は、約1300年前の歌集『万葉集』にも詠まれています。

## 今回行ったこと

* 地域の伝承を調べ、新しい登場人物をデザインしました。
* 生成AIに、作りたい絵の条件を言葉で伝えました。
* ポーズ認識AIに、自分のポーズを学習させました。AIは多数のサンプルから「体の形」の特徴を学習します。
* 全員の作品を1つの紙芝居にまとめました。

## 写真と作品の扱い

* Teachable Machineで撮影した写真は、自分のPCの中にだけあります。ワークショップの終了後、スタッフが削除します。
* 掲示板に提出したモデルのリンクには、写真そのものは含まれません。写真から取り出した「体の形」の特徴だけが含まれます。
* 掲示板は教室内だけで使用します。完成した紙芝居を教室の外で公開する場合は、改めて確認します。
