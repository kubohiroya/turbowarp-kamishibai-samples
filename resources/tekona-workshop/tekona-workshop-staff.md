参加者向け資料は[`tekona-workshop.md`](tekona-workshop.md)、用意済みの3人のモデルの事前撮影は[`pose-dataset-plan.md`](pose-dataset-plan.md)、
時代考証は[`research-notes.md`](research-notes.md)です。

# 1. 前提とねらい

## 1.1 会場と機材の前提

* 教室にプロジェクタと音響設備がある。
* 参加者1人に1台、USBカメラ付きPCを用意する。
* 生成AIはMicrosoft 365のCopilotを使う。**画像は1アカウントにつき1日2枚程度**しか作れない。
* 外部ネットワークに接続でき、Web検索ができる。
* 作品の編集にはTurboWarp Plus Editorを使う。参加者の一部はScratchの経験がある。
* 運営側で、手児奈の物語の「半完成品」SB3を用意する。
* LAN内だけで画像を投稿・共有できるWeb掲示板を用意し、素材の共有に使う。
* 進行役（教員）のほか、アシスタントがワークショップ中に、掲示板に提出された画像・セリフ・モデルを共有作品へ組み込む。

## 1.2 ねらい

* 地域の伝承を調べ、時代に合った登場人物をデザインする。
* 生成AIに条件を言葉で伝え、限られた回数で使う。
* 自分のポーズを、自分のPCでポーズ認識AIに学習させる。
* 1人1場面を持ち寄って、1つの紙芝居を完成させる。

## 1.3 作品の構成（参加者1人＝1場面）

ポーズ認識モデルは**場面ごとに1つ**しか指定できません（DSL 4.0の`recognitionModel`は場面の設定で、ポーズのアクションごとには指定できません）。
そこで、参加者が自分のPCで作ったモデルは、その参加者の場面だけで使います。

| 場面 | 内容 | モデル |
| --- | --- | --- |
| `opening`〜`well` | タイトル、真間の井と手児奈 | なし |
| `proposals` | 用意済みの3人（里の若者・国府の役人・都の貴族）。一覧（forEach）で順に再生 | 運営側の`SuitorPoses`（`stand`／`heart`／`offer`／`wide`） |
| `suitor-NN` | **参加者の求婚者**。席番号NNの順に並べる | 参加者の`PoseNN`（`stand`／`kime`） |
| `quarrel`〜`afterword` | 争い、入江、継橋、本来の言い伝え | なし |

この構成には次の利点があります。

* 写真は各参加者のPCから出ない。掲示板に出すのはモデルのリンクだけ。
* 1人のモデルが失敗しても、ほかの人の場面に影響しない。
* 全員のポーズ名が`kime`で同じなので、組み込み時に名前の食い違いが起きにくい。

## 1.4 この版の作り方（外部YAML版）

この版では、作品を次の2つのファイルで扱います（2026年8月1日回のmy-urashimaと同じ方式です）。

| ファイル | 中身 | 組み込みで変えるもの |
| --- | --- | --- |
| 作業用SB3 `tekona-workshop-4.0.sb3` | 手児奈・求婚者・ナレーションのスプライト、背景、音。台本は入っていない | Suitorスプライトに参加者の絵2枚を加える |
| 台本 `tekona.k4.yml` | 物語。参加者の場面の雛形を含む | 参加者の場面とモデルを加える（補助ページで自動） |

再生するときは、作業用SB3を開いて緑の旗 → タイトルを閉じる → メニューの「ファイルを開く」で台本を読み込みます。

**次の版はブロック台本にする予定です。** 公開App 4.0.0-rc.79のTurboWarp Plus Editorで確かめたところ、ブロック台本版ではまだ次の2点のため
ワークショップ中の組み込みに使えませんでした（[README](README.md)の「次の版（ブロック台本）の課題」）。

* 新しい素材（参加者のコスチュームやモデル）の宣言ブロックを加えると、台本文書への反映（「表示されている形式に変換して検証・保存」）が
  「Asset bundle must contain every StoryDocument asset」で止まる。
* 反映すると、`quarrel`の前につないだ新しい場面が、台本の最後（`afterword`の後）に置かれる。

このため次の版は、**素材と場面の枠をあらかじめ登録しておき、それを差し替える**方式にします（5.4節に試作の手順）。

# 2. 役割と人数の目安

| 役割 | 人数 | 主な担当 |
| --- | --- | --- |
| 進行役（教員） | 1 | 説明、プロジェクタでの上演、背景の消し方などの実演、時間管理 |
| アシスタント（組み込み） | 参加者10人に1人程度 | 掲示板の提出物を確認し、TurboWarp Plus Editorで共有作品に組み込む。数人ごとに共有作品を掲示板へ出す |
| フロアスタッフ | 1〜 | 机間巡視、Copilotの不調・撮影のサポート、写りこみ防止、撮影を望まない参加者への配慮 |

組み込みの機械的な部分（絵2枚のアップロード、補助ページへの貼り付け、台本の読み込み）は、自動リハーサルでは数秒〜十数秒で終わりました。
人の操作では、掲示板からの保存・確認を含めて**1人あたり1〜2分**を目安にします（当日のアシスタントによる練習で測ってください）。
参加者20人なら、アシスタント2人で約15〜20分です。足りない場合は、上演に出す人数を絞り、残りは終了後に組み込みます。

# 3. タイムテーブル

| 時間 | 所要 | 参加者 | アシスタント | 進行のポイント |
| --- | :---: | --- | --- | --- |
| 0:00 - 0:04 | 4分 | **導入**。伝承の紹介、用意済み3人の上演（代表者がポーズ） | 掲示板・共有作品の準備確認 | 写真の扱いを最初に説明する。席番号を確認させる |
| 0:04 - 0:11 | 7分 | **求婚者を考える**。Web検索、求婚者カード、棒人間 | 待機 | 「左右対称で上半身だけで分かるポーズ」を強調。考証メモ2.3（位色）を口頭で補う |
| 0:11 - 0:15 | 4分 | **Copilotに依頼**（1枚目で2人ならべ） | 待機 | 送信したらすぐ次へ進むよう指示する |
| 0:15 - 0:25 | 10分 | **ポーズ学習**（`stand`／`kime`）→ アップロード | 先に届いた絵とセリフから組み込み開始 | 撮影中の写りこみに注意。Copilotの結果はこの間に確認させる |
| 0:25 - 0:31 | 6分 | **仕上げと提出**（2つに分けて背景を消す → 掲示板） | 組み込み。数人ごとに共有作品を掲示板へ | 背景の消し方をプロジェクタで実演する |
| 0:31 - 0:37 | 6分 | **上演**。自分の番で前のカメラの前に立つ | 最終版を進行役へ渡す | 用意済み3人の場面は↓キーでとばす。ポーズが決まらないときはSpaceキーで進める |
| 0:37 - 0:40 | 3分 | **まとめ** | 後片付けの準備 | 再話と言い伝えのちがい、AIが学んだもの、写真の削除 |

**上演の時間**：参加者の場面は1つ約20秒です。20人で約7分になります。間に合わない場合は、上演する人を選び（例：組み込みが済んだ順）、
残りの人には掲示板の共有作品を自分のPCで見てもらいます。

## 3.1 調べ学習を増やす場合

[`research-worksheet.md`](research-worksheet.md)を使う場合の組み合わせ方です。

| 方法 | 使う章 | 時間の目安 |
| --- | --- | --- |
| 40分版のまま | 参加者向け資料1章の検索1つと求婚者カードだけ | 追加なし |
| 事前学習 | ワークシート1〜3章を事前に済ませ、当日は4章（求婚者カード）から始める | 事前に45分程度 |
| 90分版 | ワークシート1〜2章（Web検索を含む）を15分、3章を10分、4章を20分。そのあと40分版の2章以降を行う | 合計約90分 |

# 4. 事前準備

## 4.1 前日まで（運営）

1. [`pose-dataset-plan.md`](pose-dataset-plan.md)に従い、用意済み3人のモデル（`SuitorPoses`）を作り、台本に設定する。
2. `stories/tekona/`の作業用SB3`tekona-workshop-4.0.sb3`と台本`tekona.k4.yml`、
   補助ページ`resources/tekona-workshop/assistant/compose.html`をアシスタントPCに置く。
3. 5章の手順を、見本の提出（`scripts/build-tekona.ts`の`sampleSubmission`と同じ形）で通しで練習し、1人あたりの所要時間を測る。
4. 掲示板に次の投稿を用意する。
   * 「半完成品」：作業用SB3と台本（用意済みの3人まで上演できる）
   * 「素材」：`copilot/style-reference.png`、`copilot/kime-draft.png`
   * 「提出のしかた」：参加者向け資料4.2の本文テンプレート
   * 「発展課題」：参加者が自分のPCで自分の場面を試す手順（5.3）
   * 「共有作品」：組み込み済みのSB3を版ごとに出すための投稿（空）
5. 参加者用PCごとに、Copilotのアカウントにサインインしておく。参加者の年齢が利用条件に満たない場合は、操作を保護者・スタッフが行う形にする。
6. 1日の画像の作成回数が足りるよう、**本番前日以降は参加者用アカウントで画像を作らない**。

## 4.2 当日・開始前（参加者用PC）

1. USBカメラを接続し、頭から腰まで映る位置を確認する。隣の席の人が映りこまない向きにする。
2. ブラウザで次のタブを開いておく：Web検索、Copilot、Teachable Machineの「ポーズ」（`https://teachablemachine.withgoogle.com/train/pose`）、掲示板、TurboWarp Plus Editor。
3. 配布資料フォルダ（デスクトップ）に`copilot/style-reference.png`と`copilot/kime-draft.png`を置く。
4. エクスプローラーで「ファイル名拡張子」を表示する設定にする。
5. PCの画像編集アプリ（ペイント等）で、トリミングと背景の削除ができることを確認する〔要確認：会場PCのペイントの版に「背景の削除」があるか〕。

## 4.3 当日・開始前（進行役PC・アシスタントPC）

1. 進行役PC：プロジェクタと音響に接続し、半完成品で用意済み3人の上演が通ることを確認する。前のカメラの立ち位置を床にテープで示す。
2. アシスタントPC：TurboWarp Plus Editorで作業用SB3を開き、拡張機能の許可（「サンドボックスなしで実行する」を選んでOK）を済ませる。
   補助ページ`compose.html`をブラウザで開き、半完成品の台本を読み込んでおく。掲示板を並べて表示する。

# 5. 組み込みの手順（アシスタント）

## 5.1 提出物の確認

掲示板の投稿ごとに、次を確認します。足りないものは、投稿への返信かフロアスタッフ経由で参加者に伝えます。

| 確認すること | よくある問題 |
| --- | --- |
| 題名が「NN 求婚者の名前」 | 席番号の書き忘れ |
| 画像が`sNN-stand.png`と`sNN-pose.png`の2枚 | 名前の誤り、2人ならんだ絵のまま、背景が残っている |
| 本文のセリフ | 長すぎる（吹き出しは1〜2行が目安。40字程度まで） |
| モデルのリンク | `https://teachablemachine.withgoogle.com/models/…/`の形でない、まだ出ていない |
| 内容 | 他人を傷つける表現、実在の人を特定できる名前・写真 |

## 5.2 共有作品への組み込み

1人分で行うことは次の3つです。この流れは、公開App 4.0.0-rc.79とTurboWarp Plus Editorで自動リハーサル
（`pnpm verify:tekona-workshop-editor`）により、参加者の場面が`proposals`と`quarrel`の間で再生されるところまで確認済みです。

1. **絵をアップロードする（TurboWarp Plus Editor）**
   1. 掲示板から`sNN-stand.png`と`sNN-pose.png`を保存する。
   2. スプライト一覧で**Suitor**を選び、「コスチューム」タブを開く。
   3. 左下の「コスチュームを選ぶ」にマウスを重ね、「コスチュームをアップロード」から2枚を選ぶ。
   4. コスチューム名が`sNN-stand`／`sNN-pose`になっていることを確かめる（ファイル名から付く）。違う場合は名前欄を直す。
2. **台本を組み立てる（補助ページ`compose.html`）**
   1. 「2. 提出された本文」に、投稿の本文をそのまま貼る（複数人の分は「----」の行で区切る）。
   2. 表の「確認」がOKになっていることを見る。問題が出た人には、投稿への返信で直してもらう。
   3. 「台本を作って保存する」で`tekona.k4.yml`を保存する。OKの人だけが席番号順に`quarrel`の前へ入り、
      手児奈の心が「ゆれなかった」人の場面からは`Tekona.think`の行が除かれる。
3. **確かめる（TurboWarp Plus Editor）**
   1. 緑の旗 → タイトルの×で閉じる → メニューのフォルダのアイコン（Open／開く）→ 台本ファイルを開くボタン（Open story file）で、保存した`tekona.k4.yml`を選ぶ。
   2. ↓キーで場面をとばして、参加者の場面に絵とセリフが出ることを確かめる。ポーズはSpaceキーでとばせる。
   3. 誤りがあると、場所（行・列）と原因が表示される。補助ページで作った台本なら、多くはモデルのリンクの誤りか、コスチューム名の不一致。

台本は手で書き足すこともできます（`tekona.k4.yml`の「★参加者」の雛形を複製して〔 〕を埋める）。その場合も、
文字は`"`で囲み、インデントをそろえ、場面は`quarrel`の前に置きます。

## 5.3 共有作品の配布

* 数人組み込むごとに、Plus Editorの「ファイル」→「コンピューターに保存」で作業用SB3を`tekona-shared-vNN.sb3`として保存し、
  補助ページで作った`tekona.k4.yml`と**2つセットで**掲示板の「共有作品」に出す。
* 上演の前に、最後の版を進行役へ渡す。組み込みが間に合わなかった人は、その旨を進行役に伝える。
* 発展課題の参加者が自分のPCで作ったファイルは受け取らず、通常の提出物（画像・本文・リンク）から組み込む（作品の取り違えを防ぐため）。

## 5.4 次の版（ブロック台本・差し替え方式）の試作

作業用のブロック台本SB3`tekona-workshop-blocks-4.0.sb3`には、席番号01〜20（`workshop.config.json`の`slots`）の枠が登録済みです。

| 枠ごとに登録済みのもの | 中身 |
| --- | --- |
| 場面`suitor-NN` | `proposals`と`quarrel`の間に席番号順。中身は「もし［false］」で囲まれ、組み込むまで何も再生しない |
| コスチューム`sNN-stand`／`sNN-pose` | Suitorスプライトの「？」の人物の絵 |
| モデル`PoseNN` | 見本モデルのリンク（`sampleModelUrl`）、または席ごとに指定したリンク（`slotModelUrls`） |

1人分の手順は次のとおりです。TurboWarp Plus Editorでの自動リハーサル（`pnpm verify:tekona-block-workshop-editor`）で、
枠01に組み込んだ求婚者が都の貴族のあとに再生され、未記入の枠02〜20が何も再生せずに通過することを確かめました。

1. **絵を差し替える**：Suitorの「コスチューム」で参加者の絵をアップロードし、`sNN-stand`の「？」の絵を削除してから、
   アップロードした絵の名前を`sNN-stand`にする。`sNN-pose`も同じ。
2. **セリフを入れる**：場面`suitor-NN`のブロックの「（求婚者の名前）」などの欄を、提出内容に書き換える。
   手児奈の心がゆれなかった場合は、「（……ちょっとだけ、心がゆれました）」と考えるブロックを外す。
3. **使う**：場面のいちばん外側の「もし［false］」を「true」に書き換える。
4. **反映する**：台本の文書ハット（いちばん上のブロック）のアイコンを押し、「表示されている形式に変換して検証・保存」を押す。
   反映しないまま再生すると`K4-SOURCE-VIEW-UNAPPLIED`で止まる。
5. 緑の旗で再生して確かめ、「ファイル」→「コンピューターに保存」で共有作品を保存する。

**モデルのリンクは席ごとに事前登録します。** rc.79では、モデル`PoseNN`のリンクを書き換えると反映が
「Remote asset source does not match: PoseNN」で無効になるためです。運営が席ごとのモデルを事前にアップロードしておき
（[`pose-dataset-plan.md`](pose-dataset-plan.md)の「ブロック台本版：席ごとのモデル」）、そのリンクを生成時に`slotModelUrls`で枠へ入れます。
当日、参加者はその席の`seat-NN.tm`をTeachable Machineで開いて学習し直し、「クラウドモデルを更新」します。
そのため、アシスタントはモデルのブロックを触らず、提出物のモデルのリンクも不要です（確認用に書いてもらってもかまいません）。

# 6. Copilotの画像の枚数への対策

| 状況 | 対応 |
| --- | --- |
| 1枚目がうまくいった | 2枚目は使わない（ほかの用途に残す） |
| 2人ならばない、ポーズがちがう | 2枚目で、文を短くしてもう一度。「左右に2人」「重ならない」を強調する |
| 2枚とも使えない／作れない | ①「？」の人物の絵（`newcomer-stand`／`newcomer-pose`）を使い、セリフとポーズだけ自分の求婚者にする。②Scratch経験者は、見本のSVGをTurboWarpのペイントエディターで描き変える。③手描きの絵をペイントで仕上げて使う |
| Copilotが混雑・不調 | 上と同じ。待たせすぎず、ポーズ学習を先に進めさせる |

背景を消す操作（Copilotの画像編集の「背景の削除」など）が作成枚数に数えられるかは、事前に確認してください〔要確認〕。

# 7. トラブルシューティング

| 症状 | 対応 |
| --- | --- |
| 参加者の場面でモデルを読み込めない | リンクの誤りを確認。直せない場合は、その場面を「オフ」にして上演を続ける |
| `Unknown pose kime in model PoseNN` | Teachable Machineのラベルが`kime`になっていない。参加者にラベルを直してアップロードし直してもらう（同じリンクのまま更新されるかは〔要確認〕。リンクが変わったら提出し直してもらう） |
| 前のカメラでポーズが認識されにくい | 自分の席のカメラで学習したため、距離・明るさ・角度がちがう。立ち位置を席での撮影に近づける。だめならSpaceキーで進める |
| 左右が反対のポーズになる | 左右対称のポーズをすすめる。非対称の場合は、左右両方の向きで撮影してもらう |
| 絵が大きすぎる・小さすぎる | 場面の`Suitor.show`の`scale`で調整する（雛形は65） |
| カメラが使えない | ブラウザのカメラ許可を確認。Teachable MachineとTurboWarpで同時にカメラを使わない |

# 8. 終了後

1. 参加者用PCのTeachable Machineのタブを閉じ、プロジェクトを保存しない（写真を含むため）。ダウンロードフォルダ等の画像・`project.tm`を削除する。
2. Copilotのチャット履歴を削除し、サインアウトする。
3. 掲示板の投稿は、運営の方針に従って保存・削除する。参加者の絵・セリフ・名前を教室の外で公開する場合は、本人（保護者）の同意を得る。
4. アップロードされたモデル（共有リンク）には写真は含まれないが、作品を公開しない場合は台本から外す。
