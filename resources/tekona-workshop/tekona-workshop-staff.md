# 1. 前提とねらい

## 1.1 会場と機材の前提

* 教室にプロジェクタと音響設備がある。
* 参加者1人に1台、USBカメラ付きPCを用意する。
* 生成AIはMicrosoft 365のCopilotを使う。**画像は1アカウントにつき1日2枚程度**しか作れない。
* 外部ネットワークに接続でき、Web検索ができる。
* 作品の編集にはTurboWarp Plus Editorを使う。参加者の一部はScratchの経験がある。
* 運営側で、手児奈の物語の「半完成品」SB3を用意する。
* LAN内だけで画像を投稿・共有できるWeb掲示板を用意し、素材の共有に使う。
* 進行役（教員）のほか、アシスタントがワークショップ中に、掲示板に提出された画像・セリフ・モデルを共有作品へ組み込む。

## 1.2 ねらい

* 地域の伝承を調べ、時代に合った登場人物をデザインする。
* 生成AIに条件を言葉で伝え、限られた回数で使う。
* 自分のポーズを、自分のPCでポーズ認識AIに学習させる。
* 1人1場面を持ち寄って、1つの紙芝居を完成させる。

## 1.3 作品の構成と求婚者の決まり

**求婚者の決まり（用意済みの3人も参加者も同じ）**

| 決まり | 内容 |
| --- | --- |
| 構図 | 求婚者は上手（画面の右、`x: 140`）に立ち、下手（画面の左、`x: -150`）の手児奈に求婚する。絵の人物は下手（左）を向く |
| 3つの絵 | 求婚者ごとのスプライトに、コスチューム`stand`（立ち絵）・`kime`（求婚の決めポーズ）・`rejected`（断られたポーズ）。参加者は`stand.png`・`kime.png`・`rejected.png`で提出する |
| 3つのクラス | 求婚者ごとのポーズ認識モデル（Teachable Machine）に、クラス`stand`・`kime`・`rejected` |
| 流れ | 登場（`stand`）→ `kime`のポーズ認識 → 求婚 → 手児奈が断る → `rejected`のポーズ認識 → 一言 |

ポーズ認識モデルは**場面ごとに1つ**しか指定できません（DSL 4.0の`recognitionModel`は場面の設定で、ポーズのアクションごとには指定できません）。
そこで、どの求婚者も自分のスプライト・自分のモデル・自分の場面を持ちます。

| 場面 | 内容 | スプライト | モデル |
| --- | --- | --- | --- |
| `opening`〜`well` | タイトル、真間の井と手児奈 | Tekona、Narration | なし |
| `sato`・`kokufu`・`miyako` | 用意済みの3人（里の若者・国府の役人・都の貴族） | Sato・Kokufu・Miyako | 運営側の`SatoPose`・`KokufuPose`・`MiyakoPose` |
| `suitor-NN` | **参加者の求婚者**。席番号NNの順に並べる | `SuitorNN`（作業用SB3に席数ぶん用意済み） | 参加者の`PoseNN` |
| `quarrel`〜`afterword` | 争い、入江、継橋、本来の言い伝え | Tekona、Sato、Narration | なし |

この構成には次の利点があります。

* 写真は各参加者のPCから出ない。掲示板に出すのはモデルのリンクだけ。
* 1人のモデルが失敗しても、ほかの人の場面に影響しない。
* 絵の名前とクラス名が全員`stand`・`kime`・`rejected`で同じなので、組み込み時に名前の食い違いが起きにくい。

## 1.4 作品の作り方（ブロック台本版と外部YAML版）

この教材では、**ブロック台本版**を基本とし、外部YAML版を予備とします。どちらも同じ台本`tekona.k4.yml`から生成し、場面と絵の決まりは同じです。

| | ブロック台本版（基本） | 外部YAML版（予備） |
| --- | --- | --- |
| 作業用SB3 | `tekona-workshop-blocks-4.0.sb3`。台本がブロックで入っている | `tekona-workshop-4.0.sb3`。台本は入っていない |
| 参加者の場面 | 席番号01〜20の枠`suitor-NN`が登録済み。中身は「もし［false］」で囲まれ、組み込むまで何も再生しない | 補助ページで、提出された人の場面を台本`tekona.k4.yml`に加える |
| 参加者の絵 | スプライト`SuitorNN`の仮の絵3枚を差し替える | 同じ |
| 参加者のモデル | 席ごとに事前アップロードしたリンクが枠に登録済み。参加者は席の`seat-NN.tm`で学習し直し、同じリンクを更新する | 参加者がアップロードしたリンクを提出してもらい、台本に入れる |
| アシスタントの作業 | Plus Editorで枠の文を書き換え、条件をtrueにし、台本に反映する（5.2節） | 補助ページで台本を作り、作業用SB3で読み込む（5.3節） |
| 共有作品 | SB3が1つ | SB3と台本の2つセット |

**ブロック台本版を基本にする理由**：参加者が完成品をブロックで読め、共有作品がSB3 1つで済むためです。
公開App 4.0.0-rc.79のTurboWarp Plus Editorでは、ブロック台本に新しい素材（コスチューム・モデル）を加えたり、
新しい場面を`quarrel`の前に挿入したりすると、台本への反映ができません（[README](../../stories/tekona/README.md)の「ブロック台本版の制約」）。
そこで、**素材と場面の枠をあらかじめ登録しておき、それを差し替える**方式にしています。
モデルのリンクも書き換えられないため、席ごとのモデルを事前に用意します（4.1節）。

**外部YAML版を使う場合**：席ごとのモデルを事前に用意できない、21人以上で枠が足りない、Plus Editorでの反映がうまくいかない、といった場合です。

# 2. 役割と人数の目安

| 役割 | 人数 | 主な担当 |
| --- | --- | --- |
| 進行役（教員） | 1 | 説明、プロジェクタでの上演、背景の消し方などの実演、時間管理 |
| アシスタント（組み込み） | 参加者10人に1人程度 | 掲示板の提出物を確認し、TurboWarp Plus Editorで共有作品に組み込む。数人ごとに共有作品を掲示板へ出す |
| フロアスタッフ | 1〜 | 机間巡視、Copilotの不調・撮影のサポート、写りこみ防止、撮影を望まない参加者への配慮 |

組み込みの機械的な部分（絵3枚の差し替え、補助ページへの貼り付け、台本の読み込み）は、自動リハーサルでは数秒〜十数秒で終わりました。
人の操作では、掲示板からの保存・確認を含めて**1人あたり1〜2分**を目安にします（当日のアシスタントによる練習で測ってください）。
参加者20人なら、アシスタント2人で約15〜20分です。足りない場合は、上演に出す人数を絞り、残りは終了後に組み込みます。

# 3. タイムテーブル

| 時間 | 所要 | 参加者 | アシスタント | 進行のポイント |
| --- | :---: | --- | --- | --- |
| 0:00 - 0:04 | 4分 | **導入**。伝承の紹介、用意済み3人の上演（代表者がポーズ） | 掲示板・共有作品の準備確認 | 写真の扱いを最初に説明する。席番号を確認させる |
| 0:04 - 0:11 | 7分 | **求婚者を考える**。Web検索、求婚者カード、棒人間 | 待機 | 「左右対称で上半身だけで分かるポーズ」を強調。考証メモ2.3（位色）を口頭で補う |
| 0:11 - 0:15 | 4分 | **Copilotに依頼**（1枚目で`stand`・`kime`・`rejected`の3人を並べる） | 待機 | 送信したらすぐ次へ進むよう指示する |
| 0:15 - 0:25 | 10分 | **ポーズ学習**（席の`seat-NN.tm`を開き、`stand`・`kime`・`rejected`を撮影）→ クラウドモデルを更新 | 先に届いた絵とセリフから組み込み開始 | 撮影中の写りこみに注意。Copilotの結果はこの間に確認させる |
| 0:25 - 0:31 | 6分 | **仕上げと提出**（3つに分けて背景を消す → 掲示板） | 組み込み。数人ごとに共有作品を掲示板へ | 背景の消し方をプロジェクタで実演する |
| 0:31 - 0:37 | 6分 | **上演**。自分の番で前のカメラの前に立つ | 最終版を進行役へ渡す | 用意済み3人の場面は↓キーでとばす。ポーズが決まらないときはSpaceキーで進める |
| 0:37 - 0:40 | 3分 | **まとめ** | 後片付けの準備 | 再話と言い伝えのちがい、AIが学んだもの、写真の削除 |

**上演の時間**：参加者の場面は1つ約20秒です。20人で約7分になります。間に合わない場合は、上演する人を選び（例：組み込みが済んだ順）、
残りの人には掲示板の共有作品を自分のPCで見てもらいます。

## 3.1 調べ学習を増やす場合

[`research-worksheet.md`](research-worksheet.md)を使う場合の組み合わせ方です。

| 方法 | 使う章 | 時間の目安 |

# 4. 事前準備

## 4.1 前日まで（運営）

1. [`pose-dataset-plan.md`](pose-dataset-plan.md)に従い、用意済み3人のモデル（`SatoPose`・`KokufuPose`・`MiyakoPose`、各`stand`・`kime`・`rejected`）を作り、台本に設定する。
2. **席ごとのモデルを用意する（ブロック台本版）**：[`pose-dataset-plan.md`](pose-dataset-plan.md)の「ブロック台本版：席ごとのモデル」に従い、
   席数分の`seat-NN.tm`を作ってアップロードし、`pnpm tekona:seat-models collect 席ファイルのフォルダ --write`でリンクを登録する。
   席数を変える場合は、先に`stories/tekona/workshop.config.json`の`slots`を変える。
3. `pnpm update:tekona`で作業用SB3を作り直し、`stories/tekona/`の次のファイルをアシスタントPCに置く。
   * ブロック台本版：`tekona-workshop-blocks-4.0.sb3`、台本`tekona.k4.yml`（補助ページで文の一覧を作るため）
   * 外部YAML版（予備）：`tekona-workshop-4.0.sb3`、台本`tekona.k4.yml`
   * 補助ページ`resources/tekona-workshop/assistant/compose.html`
4. **開き直した`seat-NN.tm`から同じリンクを更新できることを、1席分で確かめる**〔要確認〕。
   `seat-01.tm`を開いて写真を撮り直し、「クラウドモデルを更新」したあと、ブロック台本版の枠01でその変更が認識に反映されることを見る。
5. 5章の手順を、見本の提出（`scripts/build-tekona.ts`の`sampleSubmission`と同じ形）で通しで練習し、1人あたりの所要時間を測る。
6. 掲示板に次の投稿を用意する。
   * 「半完成品」：作業用SB3`tekona-workshop-blocks-4.0.sb3`（用意済みの3人まで上演できる）
   * 「素材」：`copilot/style-reference.png`、`copilot/pose-draft.png`
   * 「提出のしかた」：参加者向け資料4.2の本文テンプレート
   * 「発展課題」：参加者が自分のPCで自分の場面を試す手順（参加者向け資料4.3）
   * 「共有作品」：組み込み済みのSB3を版ごとに出すための投稿（空）
7. 参加者用PCごとに、Copilotのアカウントにサインインしておく。参加者の年齢が利用条件に満たない場合は、操作を保護者・スタッフが行う形にする。
8. 1日の画像の作成回数が足りるよう、**本番前日以降は参加者用アカウントで画像を作らない**。

## 4.2 当日・開始前（参加者用PC）

1. USBカメラを接続し、頭から腰まで映る位置を確認する。隣の席の人が映りこまない向きにする。
2. ブラウザで次のタブを開いておく：Web検索、Copilot、Teachable Machineの「ポーズ」（`https://teachablemachine.withgoogle.com/train/pose`）、掲示板、TurboWarp Plus Editor。
3. 配布資料フォルダ（デスクトップ）に`copilot/style-reference.png`、`copilot/pose-draft.png`、**その席の`seat-NN.tm`**を置く。
   席のPCと席番号の札、`seat-NN.tm`の番号が一致していることを確かめる。
4. エクスプローラーで「ファイル名拡張子」を表示する設定にする。
5. PCの画像編集アプリ（ペイント等）で、トリミングと背景の削除ができることを確認する〔要確認：会場PCのペイントの版に「背景の削除」があるか〕。

## 4.3 当日・開始前（進行役PC・アシスタントPC）

1. 進行役PC：プロジェクタと音響に接続し、半完成品で用意済み3人の上演が通ることを確認する。前のカメラの立ち位置を床にテープで示す。
2. アシスタントPC：TurboWarp Plus Editorで`tekona-workshop-blocks-4.0.sb3`を開き、拡張機能の許可（「サンドボックスなしで実行する」を選んでOK）を済ませる。
   補助ページ`compose.html`をブラウザで開き、版を「ブロック台本版」にして、台本`tekona.k4.yml`を読み込んでおく。掲示板を並べて表示する。
3. アシスタントが2人以上いる場合は、**担当する席を分ける**（例：01〜10と11〜20）。同じSB3を2人で同時に編集できないため、
   各自が自分の担当分を組み込んだSB3を保存し、上演前に1人がもう一方の分を組み込む。または、担当を交代しながら1つのSB3を順に回す。

# 5. 組み込みの手順（アシスタント）

## 5.1 提出物の確認

掲示板の投稿ごとに、次を確認します。足りないものは、投稿への返信かフロアスタッフ経由で参加者に伝えます。

| 確認すること | よくある問題 |
| --- | --- |
| 題名が「NN 求婚者の名前」 | 席番号の書き忘れ |
| 画像が`stand.png`・`kime.png`・`rejected.png`の3枚 | 名前の誤り、3人ならんだ絵のまま、背景が残っている、人物が下手（左）を向いていない |
| 本文のセリフ | 長すぎる（吹き出しは1〜2行が目安。40字程度まで） |
| モデルのリンク | `https://teachablemachine.withgoogle.com/models/…/`の形でない、まだ出ていない |
| 内容 | 他人を傷つける表現、実在の人を特定できる名前・写真 |

## 5.2 共有作品への組み込み（ブロック台本版）

作業用のブロック台本SB3`tekona-workshop-blocks-4.0.sb3`には、席番号01〜20（`workshop.config.json`の`slots`）の枠が登録済みです。

| 枠ごとに登録済みのもの | 中身 |
| --- | --- |
| 場面`suitor-NN` | 用意済みの3人（`miyako`）と`quarrel`の間に席番号順。中身は「もし［false］」で囲まれ、組み込むまで何も再生しない |
| スプライト`SuitorNN`とコスチューム`stand`・`kime`・`rejected` | 「？」の人物の仮の絵 |
| モデル`PoseNN` | その席の`seat-NN.tm`でアップロードしたリンク（`slotModelUrls`）。未登録の席は見本モデル（`sampleModelUrl`） |

1人分で行うことは次の5つです。公開App 4.0.0-rc.91とTurboWarp Plus Editorでの自動リハーサル（`pnpm verify:tekona-block-workshop-editor`）で、
補助ページの一覧どおりに枠01を書き換え（手児奈の心が揺れなかった場合の削除を含む）、反映・再生・保存までを確かめました。
組み込んだ枠は都の貴族のあとに再生され、未記入の枠は何も再生せずに通過します。

1. **文の一覧を作る（補助ページ`compose.html`）**
   1. 「2. 提出された本文」に、投稿の本文をそのまま貼る（複数人の分は「----」の行で区切る）。
   2. 表の「確認」がOKになっていることを見る。問題が出た人には、投稿への返信で直してもらう。ブロック台本版ではモデルのリンクは不要。
   3. 「3. 枠に入れる文」に、席ごとの一覧（ブロック・いまの文・入れる文）が出る。
2. **絵を差し替える（Plus Editor）**
   1. 掲示板から`stand.png`・`kime.png`・`rejected.png`を、席番号ごとのフォルダに保存する（ファイル名は全員同じなので混ぜない）。
   2. スプライト一覧で、その席のスプライト**`SuitorNN`**（例：`Suitor07`）を選び、「コスチューム」タブを開く。
   3. 仮の絵`stand`を右クリック→「削除」してから、左下の「コスチュームを選ぶ」にマウスを重ね、「コスチュームをアップロード」で`stand.png`を選ぶ。
      `kime`・`rejected`も同じようにする（先に削除しておくと、アップロードした絵の名前がファイル名のまま`stand`などになる）。
   4. コスチューム名が`stand`・`kime`・`rejected`の3つだけになっていることを確かめる。違う場合は名前欄を直す。
3. **文を書き換える（Plus Editor）**
   1. ステージを選び、「コード」タブで場面`suitor-NN`のブロックを探す（右クリック→「きれいにする」は使わない）。
   2. 一覧の上から順に、「いまの文」が入っている欄をクリックし、中身をすべて選択して消してから、一覧の「コピー」で写した「入れる文」を貼る。
      ナレーションの欄は、作者名と求婚者名を含む文全体を1回で置き換える。
   3. 一覧に「このブロックを外して削除する」とある場合（手児奈の心が揺れなかった人）は、「（……ちょっとだけ、心が揺れました）」と考えるブロックを
      ドラッグして外し、ブロックパレットへ捨てる。下のブロックがつながったままになっていることを確かめる。
   4. 場面のいちばん外側の「もし」の`false`を`true`に書き換える。
4. **台本に反映する**：台本の文書ハット（いちばん上のブロック）のアイコンを押し、「表示されている形式に変換して検証・保存」を押す。
   反映しないまま再生すると`K4-SOURCE-VIEW-UNAPPLIED`で止まる。反映できない場合は、表示された行・列と原因を確認し、
   多くは文の中の`"`や`\`（使えない記号）、ブロックの外し方の誤り。直せない場合は、その枠の「もし」を`false`に戻して反映する。
5. **確かめる**：緑の旗 → タイトルの×で閉じる → ↓キーで場面をとばして、参加者の場面に絵とセリフが出ることを確かめる。ポーズはSpaceキーでとばせる。

**モデルのブロックは触りません。** rc.91でも、モデル`PoseNN`のリンクを書き換えると反映が
「Remote asset source does not match: PoseNN」で無効になるためです。リンクは席ごとに決まっていて、参加者がその席の`seat-NN.tm`で
「クラウドモデルを更新」すると、同じリンクのモデルが参加者のポーズに置き換わります（[`pose-dataset-plan.md`](pose-dataset-plan.md)）。

## 5.3 共有作品への組み込み（外部YAML版・予備）

1人分で行うことは次の3つです。この流れは、公開App 4.0.0-rc.91とTurboWarp Plus Editorで自動リハーサル
（`pnpm verify:tekona-workshop-editor`）により、参加者の場面が用意済みの3人のあと、`quarrel`の前で再生されるところまで確認済みです。

1. **絵をアップロードする**：5.2節の2.と同じ（作業用SB3は`tekona-workshop-4.0.sb3`）。
2. **台本を組み立てる（補助ページ`compose.html`）**
   1. 版を「外部YAML版」にし、「2. 提出された本文」に投稿の本文をそのまま貼る。
   2. 表の「確認」がOKになっていることを見る（この版ではモデルのリンクが必要）。
   3. 「台本を作って保存する」で`tekona.k4.yml`を保存する。OKの人だけが席番号順に`quarrel`の前へ入り、
      手児奈の心が「揺れなかった」人の場面からは`Tekona.think`の行が除かれる。
3. **確かめる**
   1. 緑の旗 → タイトルの×で閉じる → メニューのフォルダのアイコン（Open／開く）→ 台本ファイルを開くボタン（Open story file）で、保存した`tekona.k4.yml`を選ぶ。
   2. ↓キーで場面をとばして、参加者の場面に絵とセリフが出ることを確かめる。ポーズはSpaceキーでとばせる。
   3. 誤りがあると、場所（行・列）と原因が表示される。補助ページで作った台本なら、多くはモデルのリンクの誤りか、コスチューム名の不一致。

台本は手で書き足すこともできます（`tekona.k4.yml`の「★参加者」の雛形を複製して〔 〕を埋める）。その場合も、
文字は`"`で囲み、インデントをそろえ、場面は`quarrel`の前に置きます。

## 5.4 共有作品の配布

* 数人組み込むごとに、Plus Editorの「ファイル」→「コンピューターに保存」で作業用SB3を`tekona-shared-vNN.sb3`として保存し、掲示板の「共有作品」に出す。
  外部YAML版では、補助ページで作った`tekona.k4.yml`と**2つセットで**出す。
* 上演の前に、最後の版を進行役へ渡す。組み込みが間に合わなかった人は、その旨を進行役に伝える。
* 発展課題の参加者が自分のPCで作ったファイルは受け取らず、通常の提出物（画像・本文）から組み込む（作品の取り違えを防ぐため）。

# 6. Copilotの画像の枚数への対策

| 状況 | 対応 |
| --- | --- |
| 1枚目がうまくいった | 2枚目は使わない（ほかの用途に残す） |
| 3人が並ばない、ポーズが違う、向きが違う | 2枚目で、文を短くして再度依頼する。「横一列に3人」「左・中央・右を、棒人間の同じ位置の姿勢に」「重ならない」「左を向く」を強調する |
| 2枚とも使えない／作れない | ①席のスプライトの「？」の仮の絵をそのまま使い、セリフとポーズだけ自分の求婚者にする。②Scratch経験者は、見本のSVGをTurboWarpのペイントエディターで描き変える。③手描きの絵をペイントで仕上げて使う |
| Copilotが混雑・不調 | 上と同じ。待たせすぎず、ポーズ学習を先に進めさせる |

背景を消す操作（Copilotの画像編集の「背景の削除」など）が作成枚数に数えられるかは、事前に確認してください〔要確認〕。

# 7. トラブルシューティング

| 症状 | 対応 |
| --- | --- |
| 参加者の場面でモデルを読み込めない | ブロック台本版：その席の`seat-NN.tm`で「クラウドモデルを更新」が済んでいるか確認する。外部YAML版：リンクの誤りを確認する。直せない場合は、その場面の「もし」を`false`に戻して（外部YAML版では台本から外して）上演を続ける |
| 参加者の場面で、仮のポーズ（スタッフのポーズ）しか認識されない | ブロック台本版で、参加者が`seat-NN.tm`を開かずに新しいプロジェクトで学習したか、「モデルをアップロード」を押した（別のリンクになる）。`seat-NN.tm`を開き直し、写真を撮り直して「クラウドモデルを更新」してもらう |
| 反映で`Asset bundle must contain every StoryDocument asset`／`Remote asset source does not match` | ブロック台本版で、素材やモデルのブロックを加えた・書き換えた。Plus Editorの「編集」→「元に戻す」で戻すか、直前に保存した共有作品から組み込み直す |
| `Unknown pose kime in model PoseNN`（または`rejected`） | Teachable Machineのラベルが`stand`・`kime`・`rejected`になっていない。参加者にラベルを直して「クラウドモデルを更新」してもらう（外部YAML版でリンクが変わった場合は提出し直してもらう） |
| 前のカメラでポーズが認識されにくい | 自分の席のカメラで学習したため、距離・明るさ・角度がちがう。立ち位置を席での撮影に近づける。だめならSpaceキーで進める |
| 左右が反対のポーズになる | 左右対称のポーズをすすめる。非対称の場合は、左右両方の向きで撮影してもらう |
| 絵が大きすぎる・小さすぎる | 場面の`SuitorNN.show`の`scale`で調整する（雛形は65） |
| カメラが使えない | ブラウザのカメラ許可を確認。Teachable MachineとTurboWarpで同時にカメラを使わない |

# 8. 終了後

1. 参加者用PCのTeachable Machineのタブを閉じ、プロジェクトを保存しない（写真を含むため）。ダウンロードフォルダ等の画像・`project.tm`を削除する。
2. Copilotのチャット履歴を削除し、サインアウトする。
3. 掲示板の投稿は、運営の方針に従って保存・削除する。参加者の絵・セリフ・名前を教室の外で公開する場合は、本人（保護者）の同意を得る。
4. アップロードされたモデル（共有リンク）には写真は含まれないが、作品を公開しない場合は台本から外す。
