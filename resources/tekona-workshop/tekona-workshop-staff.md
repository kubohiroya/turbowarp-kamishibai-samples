# 1. 形式とねらい

* 進行役（講師）のPC 1台をスクリーンに映し、参加者全員で1つの作品をつくる**一斉進行**です。参加者の個別PC操作は前提にしません。
* メインは後半の「4人目の求婚者づくり」と「Teachable Machineでのポーズ学習」です。前半の体験は短く切り上げます。
* 学ぶこと：地域の伝承の再話、キャラクター・ポーズの設計、機械学習のサンプル収集と学習・評価、台本の一覧（表）に1行足すと場面がふえること。

# 2. 役割

| 役割 | 人数 | 主な担当 |
| --- | --- | --- |
| 進行役 | 1 | 説明、アイデアのとりまとめ、TurboWarpでの作画、台本の書き換え |
| 操作スタッフ | 1 | Teachable Machineの操作（クラス追加・撮影・学習・アップロード）、URLの受け渡し |
| フロアスタッフ | 1〜 | 撮影時の安全確保・写りこみ防止、撮影を望まない参加者への配慮、アイデアシートの回収 |

進行役と操作スタッフが別PCを使うと、作画（3章）と学習の準備（4章）を並行できます。1人で行う場合は各章を短縮します。

# 3. タイムテーブル

| 時間 | 所要 | 内容 | 進行のポイント |
| --- | :---: | --- | --- |
| 0:00 - 0:04 | 4分 | **導入** | 真間の井・手児奈の紹介。今日は「求婚者になりきる」「4人目をつくる」の2つ。撮影と写真の扱いを最初に説明する |
| 0:04 - 0:10 | 6分 | **紙芝居を体験** | 3人の求婚者を代表3人が演じる。ポーズが決まらないときはSpaceキーでスキップしてテンポを保つ |
| 0:10 - 0:17 | 7分 | **4人目を考える** | シートの6項目を挙手・付箋で集め、2〜3案から拍手で決める。決めポーズは既存4クラスと違うか、上半身で区別できるかをその場で確認する |
| 0:17 - 0:22 | 5分 | **4人目の絵** | 進行役がTurboWarpで作画（5章）。並行して操作スタッフがTeachable Machineを準備 |
| 0:22 - 0:32 | 10分 | **ポーズ学習** | クラス`new`を追加して撮影 → 学習 → プレビューで5クラスを確認 → アップロード（6章） |
| 0:32 - 0:37 | 5分 | **台本に加えて上演** | 4人目の行を有効化・URL差し替え・読み込み（7章）。4人目の場面を中心に上演 |
| 0:37 - 0:40 | 3分 | **まとめ** | 再話と本来の言い伝えのちがい、AIが学んだもの、写真の削除 |

時間が押した場合は、1章の体験を1人分に縮め、7章の上演は`proposals`の4人目から始めます（ArrowDownで場面をとばせます）。

# 4. 事前準備

## 4.1 前日まで

1. [`pose-dataset-plan.md`](pose-dataset-plan.md)に従い、`stand`／`heart`／`offer`／`wide`の4クラスを撮影した`project.tm`を用意する。
2. その`project.tm`で学習・アップロードしたモデルのURLを`tekona.k4.yml`の`SuitorPoses`へ設定し、3人分の上演を通しで確認する。
   これが当日モデルづくりに失敗したときの**予備モデル**になる。
3. 予備として、4人目まで含めた見本モデル（スタッフが`new`クラスに仮のポーズを撮ったもの）も作っておくと安心。
4. 作品のSB3（ワークショップ用、台本を外部から読み込む版）、`tekona.k4.yml`、`project.tm`を進行役PCに置く。
5. 進行役PCのTurboWarp（エディター）で、SB3を開き、拡張機能の許可（「サンドボックスなしで実行する」）を済ませておく。

## 4.2 当日・開始前

1. USBカメラを接続し、スクリーン側から立ち位置（カメラから約2〜3m、頭から腰まで写る位置）を床にテープで示す。
2. 背景に人の往来が入らない向きにカメラを置く。可能なら無地の壁やクロマキー背景の前にする。
3. Edgeで次のタブを開いておく。
   * Teachable Machine（`project.tm`を「ファイルからプロジェクトを開く」で読み込み済み）
   * TurboWarp（作品SB3を読み込み済み）
4. `tekona.k4.yml`をテキストエディターで開き、4人目の8行の位置を確認しておく。
5. 予備モデルのURLで、上演が最後まで通ることを確認する。

# 5. 4人目の絵をつくる（進行役）

求婚者の絵はTurboWarpで編集できるベクター画像（SVG）です。参加者の声を聞きながら描き変えます。

1. TurboWarpで**Suitor**スプライトを選び、「コスチューム」タブを開く。
2. 参加者のイメージに近い既存の求婚者（`sato-stand`など）を右クリック→「複製」し、その中身をすべて選択してコピーする。
3. `newcomer-stand`を選び、中身を消してから貼り付け、服の色・ぼうし・持ち物などを描き変える。
4. 同じように`newcomer-pose`をつくる。うでの線を「形を変える」ツールで動かし、決めた決めポーズにする。
5. **コスチューム名`newcomer-stand`／`newcomer-pose`は変えない。**複製したコスチューム（`sato-stand2`など）は削除する。
6. ファイル → コンピューターに保存 でSB3を保存する。

代わりの方法：

* 生成AI（例：M365 Copilot）が使える場合は、既存の立ち絵の画像と棒人間の下書きを添付し、
  「立ち絵の人物を、指定した服装・持ち物に変え、棒人間のポーズに描き直してください。背景は #00FF00 の緑一色」と依頼し、
  背景を削除したPNGを`newcomer-*`へアップロードする。利用規約上の年齢制限があるため、操作は大人が行う。
* 時間がないときは、仮の「？」の絵のまま進める（ポーズとセリフだけが新しい求婚者になる）。

# 6. ポーズを学習させる（操作スタッフ）

1. Teachable Machineで事前撮影済みの`project.tm`が開いていることを確認する（クラス`stand`／`heart`／`offer`／`wide`）。
2. 「クラスを追加」でクラスを1つ追加し、ラベルを半角小文字で**`new`**にする。
3. 参加者3〜5人に交代で立ってもらい、`new`のポーズを1人あたり約20〜40枚（数秒の長押し）撮影する。
   * 腕の角度を少し変える、前後に半歩動くなど、ゆらぎを入れてもらう。
   * ボーン（関節の丸と線）が出ていないサンプル、写りこみのあるサンプルは削除する。
   * 撮影を望まない参加者には、無理に依頼しない。スタッフが代わりに撮影されてもよい。
4. 余裕があれば、撮影した人に`stand`（気をつけ）も数枚追加で撮ってもらう（会場の照明・服装に合わせるため）。
5. 「モデルをトレーニングする」を押す（1〜2分）。待つあいだに、参加者向け資料の「考えてみよう」を問いかける。
6. プレビューで、`stand`・3人分・`new`の5つのポーズを順にとり、それぞれ正しいクラスの棒グラフが伸びるか確認する。
   紛らわしい場合は、そのクラスのサンプルを追加して再トレーニングする。
7. 「モデルをエクスポートする」→「アップロード（共有可能なリンク）」→「モデルをアップロード」。
   「クラウドモデルは最新です」を確認し、共有リンクをコピーして進行役へ渡す。

**ラベルは台本の`pose`と完全に一致させる。**一致しないと、その求婚者の場面で
`K4-POSE-PORT-003: Unknown pose new in model SuitorPoses`と表示されて停止します。

# 7. 台本に加えて上演する（進行役）

1. `tekona.k4.yml`の`SuitorPoses`の`url:`を、コピーした共有リンクに置き換える。
2. 求婚者の一覧（`items`）の末尾にある4人目の8行で、行頭の`# `（シャープと空白）を外す。インデントはそろえたままにする。
3. `name`・`poseHint`・`proposal`・`refusal`を参加者の案に書き換え、`moved`を`true`（心がゆれた）か`false`にする。
4. 保存し、TurboWarpで緑の旗 → タイトルを閉じる → メニューの「ファイルを開く」で`tekona.k4.yml`を読み込む。
5. 台本の誤りがあると、場所（行・列）を示した表示が出る。多くはインデントのずれか、`# `の外し忘れ。

ブロック台本版を使う場合は、`proposals`の「一覧」ブロックの編集アイコンから表のフォームを開き、行を追加して同じ値を入力します。

# 8. トラブルシューティング

| 症状 | 対応 |
| --- | --- |
| 求婚の場面でモデルを読み込めない | ネットワークを確認。だめなら予備モデルのURLへ戻す |
| `Unknown pose … in model SuitorPoses` | Teachable Machineのラベル（`heart`／`offer`／`wide`／`new`）と台本の`pose`の綴りを合わせる |
| ポーズがなかなか認識されない | 立ち位置・明るさを確認。だめならSpaceキーでスキップして進行を優先し、終了後に原因を説明する |
| 4人目と既存のポーズを取り違える | 4人目のポーズを少し大げさにする。または`new`のサンプルを追加して再学習 |
| Teachable Machineの学習・アップロードが終わらない | 予備の「4人目まで含めた見本モデル」のURLを使う |
| カメラが使えない | ブラウザのカメラ許可を確認。TurboWarpとTeachable Machineで同時にカメラを使わない（片方のタブのカメラを止める） |

# 9. 終了後

1. Teachable Machineのプロジェクトを当日分も含めて保存する場合は、参加者が写った写真を含むため、**配布・公開しない**。
   原則として当日撮影分は保存せず、ブラウザのタブを閉じて破棄する。
2. ダウンロードフォルダ等に残った`project.tm`・画像を削除し、ごみ箱を空にする。
3. アップロードしたモデル（共有リンク）には写真は含まれないが、不要になったら台本から外す。
4. 4人目の絵・セリフを今後のサンプルに使う場合は、考えた参加者（保護者）に利用の可否とクレジットの表記を確認する。
