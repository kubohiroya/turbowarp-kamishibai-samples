# ポーズ学習用データの撮影計画

「手児奈」の用意済みの求婚者8人のポーズ認識モデル（台本の`SatoPose`・`KokufuPose`・`MiyakoPose`）のために、
ワークショップ前に用意しておくTeachable Machine Poseプロジェクト（`.tm`）の撮影計画です。
参加者の求婚者のモデルは、当日に参加者が自分のPCで作ります（このページの後半）。
人物の写真を含むため、撮影はスタッフなど**撮影と利用に同意した人**だけで行います。

## 決まり：どのモデルもクラスは stand・kime・rejected

用意済みの8人も参加者も、**求婚者1人につきモデル1つ**で、クラス（ラベル）は次の3つです。
求婚者のスプライトのコスチューム名（`stand`・`kime`・`rejected`）と同じ名前にそろえます。

| ラベル（半角小文字） | ポーズ | 紙芝居で使うところ |
| --- | --- | --- |
| `stand` | 気をつけ。両うでを体の横に下ろす | 何もしていない状態。ポーズの誤認識を防ぐ |
| `kime` | その求婚者の、求婚の決めポーズ | 「カメラの前で、求婚のポーズを決めよう！」 |
| `rejected` | その求婚者の、断られてがっかりしたポーズ | 「断られた……。がっかりのポーズ！」 |

ラベルが1文字でも違うと、その場面で`K4-POSE-PORT-003: Unknown pose kime in model …`のように停止します。

顔の表情や小道具の違いではなく、腕・頭・上体の位置で3クラスを区別できるように撮影します。

### モデル未作成の間の設定

モデルはこれから作ります。用意済み8人と参加者用の見本には、実在する代替URL
`https://sqs.prof.cuc.ac.jp/kamishibai/20260630/6and7/`を設定しています。
「地震だ！頭を守ろう」のモデルと同じ重みを持つ元モデルで、クラスは`open1`・`open2`・`open3`・`despair`です。
`stand`・`kime`・`rejected`には対応しないため、代替URLを使うポーズ処理は個別に無効化してあります。
YAMLでは`invalidate: {condition: false, then: […]}`、ブロック台本ではC型の「この部分を使う：オフ」です。
参加者の場面全体の「もし」を`true`にしても、代替モデルのポーズ処理は無効のままです。

| 対象 | 実モデルのURLを入れる場所 |
| --- | --- |
| 里の若者 | `stories/tekona/tekona.k4.yml`の`assets.SatoPose.source.url` |
| 国府の役人 | 同じ台本の`assets.KokufuPose.source.url` |
| 都の貴族 | 同じ台本の`assets.MiyakoPose.source.url` |
| 入江の漁師 | 同じ台本の`assets.RyoshiPose.source.url` |
| 歌の上手な若者 | 同じ台本の`assets.UtabitoPose.source.url` |
| 機織りの名人の若者 | 同じ台本の`assets.HataoriPose.source.url` |
| 郡司の息子 | 同じ台本の`assets.GunjiPose.source.url` |
| 防人に出る若者 | 同じ台本の`assets.SakimoriPose.source.url` |
| 参加者用の見本 | `stories/tekona/workshop.config.json`の`blockWorkshop.sampleModelUrl` |
| 参加者の席01〜20（当日の編集） | SB3の内部ルート文書`tekona.k4.yml`の`assets.PoseNN.source.url`（NNは席番号）。モデル宣言ブロックのリンクを書き換える |
| 参加者の席01〜20（運営が事前登録する場合） | `workshop.config.json`の`blockWorkshop.slotModelUrls`のキー`"01"`〜`"20"` |

用意済み8人はURLの置換に加えて、その人物の`kime`・`rejected`を囲む2つの`invalidate.condition`を`true`にします。
参加者の場面は、合成時に代替URLなら個々のポーズを無効化し、実モデルのURLなら有効なポーズを生成します。
設定後は`pnpm update:tekona`でSB3を再生成し、実際の3クラスの認識を確認します。
配布済みSB3をEditorで編集する場合、モデル宣言は共通ルート`tekona.k4.yml`から反映し、
ポーズ用のオン/オフとセリフは担当のシーン文書から別々に反映します。
既に生成済みのブロックを手で有効にする場合も、実モデルへの差し替え・再生成を先に行ってください。

専用書式には`invalidate`対応Appが必要です。このリポジトリが固定するApp 4.0.13は未対応のため、現在は未公開プレビューで検証します。
対応版ではオフの本体もYAMLに保持し、編集・反映・保存・再読み込みの往復で復元します。
汎用`if`を生成後だけ専用ブロックへ差し替える旧処理は使用しません。

## 撮影条件

* 撮影者：3人以上。背の高さ・体格・服の色（明るい色と暗い色）がちがう人を含める。
* 位置：カメラから約2〜3m。**頭から腰まで**が確実に写り、うでを広げても画面からはみ出さない。
* カメラ：当日と同じ機種・同じ高さ（目の高さ程度）。可能なら当日と同じ会場・照明でも一部を撮る。
* 背景：無地が望ましい。他の人が写りこんだサンプルは削除する。
* 左右：国府の役人の`kime`は左右非対称のポーズです。右手をさしだす形と左手をさしだす形の**両方**を同じ`kime`に入れ、
  どちらの手でも認識されるようにします（Teachable Machineと紙芝居でカメラ映像の左右反転の設定が違っても困らないようにするため）。

## 枚数の目安（モデル1つあたり）

| クラス | 1人あたり | 合計（3人の場合） |
| --- | --- | --- |
| `stand` | 40〜60枚 | 120〜180枚 |
| `kime`・`rejected` | 各30〜40枚 | 各90〜120枚 |

* 1回の長押しで数秒撮影し、そのあいだに腕の角度・体の向き・前後の位置を少しずつ変えます。
* ボーン（関節の丸と線）が表示されていないサンプルは削除します。
* 当日これらのプロジェクトを再トレーニングすることはありません。枚数は認識のしやすさを優先して決めてかまいません。

## 確認

1. トレーニング後、プレビューで5人以上（撮影に参加していない人を含む）に3つのポーズをとってもらい、正しいクラスが最も高くなることを確認する。
2. 「気をつけ」や移動中の姿勢で、`kime`・`rejected`が誤って高くならないことを確認する。
3. 8つのモデルをアップロードし、共有リンクを`tekona.k4.yml`の上表の8モデルの`assets.<モデル名>.source.url`へ設定して、紙芝居で8人分のポーズが認識されることを確認する。
4. 参加者の場面の動作確認用に、スタッフが`stand`・`kime`・`rejected`の3クラスで見本モデルを1つ作り（`workshop.config.json`の`sampleModelUrl`）、雛形の確認に使う。

## 保存と取り扱い

* `project.tm`には写真が含まれます。リポジトリへコミットせず、配布物にも入れません（必要な場合は撮影者全員の同意を得たうえで別途判断します）。
* スタッフ間の受け渡しは、アクセスを限定した保存場所で行います。
* アップロードしたモデル（共有リンク）には写真は含まれず、写真を復元することもできません。台本に書くのはこのリンクだけです。
* 当日に参加者を撮影したサンプルは、原則として保存せず、終了後に破棄します（スタッフ向け資料の「8. 終了後」）。

## ブロック台本版：参加者が自分のモデルを作る

参加者は自分のモデルを**新規に作り**、クラウドへエクスポートし、台本の自分の枠のモデルのリンクを自分のURLへ書き換えます。
運営が席ごとのモデルを事前に用意することはしません。手間がかかるうえ、当日モデルが更新されない席が残る危険があるためです。

### 手順（参加者）

1. Teachable Machineの「ポーズプロジェクト」を**新しく**開く。既存のプロジェクトファイルは使わない。
2. クラスを3つにし、名前を`stand`・`kime`・`rejected`にする。名前は全員同じで、1文字でも違うと台本から参照できない。
3. 自分で各クラス30〜50枚撮る。`stand`は気をつけ、`kime`は自分の決めポーズ、`rejected`は自分のがっかりのポーズ。
4. 「モデルをトレーニングする」。
5. 「モデルをエクスポートする」→「モデルをアップロード（クラウドに共有）」→**共有リンクをひかえる**。
   リンクは`https://teachablemachine.withgoogle.com/models/`で始まる。
6. 台本の自分の枠のモデルのリンクを、ひかえたリンクへ書き換える。

プロジェクトファイル（`.tm`）の保存・提出は不要です。参加者が撮った写真は、その参加者のPCのブラウザの中だけにあります。

### 必要なApp

リンクの書き換えは、**App 4.0.11以降**が必要です。4.0.10までの公開Appでは、台本への反映が
`Remote asset source does not match: PoseNN`で拒否されます（kubohiroya/turbowarp-kamishibai-app#1184）。
現在の固定版は`app-release.json`を参照してください。ダミー認識の専用無効化には、さらに`invalidate-source-v1`対応版が必要です。
その対応版の公開・依存更新前は、明示的な未公開プレビューで検証します。

### 取り扱い

* 参加者のモデルの共有リンクは、その参加者のポーズを公開する先です。ワークショップ後に不要なら、Teachable Machineから削除できます。
* 参加者の写真を含むプロジェクトファイルは、このリポジトリへコミットしません。
