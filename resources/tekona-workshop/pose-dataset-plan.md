# ポーズ学習用データの撮影計画

「手児奈」の用意済みの求婚者3人のポーズ認識モデル（台本の`SuitorPoses`）のために、ワークショップ前に用意しておくTeachable Machine Poseプロジェクト（`project.tm`）の撮影計画です。
参加者の求婚者のモデルは、当日に参加者が自分のPCで作ります（このページの最後）。
人物の写真を含むため、撮影はスタッフなど**撮影と利用に同意した人**だけで行います。

## クラス

| ラベル（半角小文字） | ポーズ | 用途 |
| --- | --- | --- |
| `stand` | 気をつけ。両うでを体の横に下ろす。手を軽く組む・体の前で水がめを持つ形も含める | 何もしていない状態。ポーズの誤認識を防ぐ |
| `heart` | 両うでで頭の上に大きなハート（手先を頭上で合わせ、ひじを横へ張る） | 里の若者 |
| `offer` | 片手を胸に当て、もう片方の手を横へさしだす | 国府の役人 |
| `wide` | 両うでを肩の高さで横へまっすぐ広げる | 都の貴族 |

ラベルは台本`tekona.k4.yml`の求婚者一覧の`pose`列と完全に一致させます。順番は問いません。

## 撮影条件

* 撮影者：3人以上。背の高さ・体格・服の色（明るい色と暗い色）がちがう人を含める。
* 位置：カメラから約2〜3m。**頭から腰まで**が確実に写り、うでを広げても画面からはみ出さない。
* カメラ：当日と同じ機種・同じ高さ（目の高さ程度）。可能なら当日と同じ会場・照明でも一部を撮る。
* 背景：無地が望ましい。他の人が写りこんだサンプルは削除する。
* 左右：`offer`は左右非対称のポーズです。右手をさしだす形と左手をさしだす形の**両方**を同じ`offer`に入れ、
  どちらの手でも認識されるようにします（Teachable Machineと紙芝居でカメラ映像の左右反転の設定が違っても困らないようにするため）。

## 枚数の目安

| クラス | 1人あたり | 合計（3人の場合） |
| --- | --- | --- |
| `stand` | 40〜60枚 | 120〜180枚 |
| `heart`／`offer`／`wide` | 各30〜40枚 | 各90〜120枚 |

* 1回の長押しで数秒撮影し、そのあいだに腕の角度・体の向き・前後の位置を少しずつ変えます。
* ボーン（関節の丸と線）が表示されていないサンプルは削除します。
* 当日このプロジェクトを再トレーニングすることはありません。枚数は認識のしやすさを優先して決めてかまいません。

## 確認

1. トレーニング後、プレビューで5人以上（撮影に参加していない人を含む）に各ポーズをとってもらい、正しいクラスが最も高くなることを確認する。
2. 「気をつけ」や移動中の姿勢で、求婚者のクラスが誤って高くならないことを確認する。
3. モデルをアップロードし、共有リンクを`tekona.k4.yml`の`SuitorPoses`へ設定して、紙芝居で3人分のポーズが認識されることを確認する。
4. 参加者の場面の動作確認用に、スタッフが`stand`／`kime`の2クラスで見本モデルを1つ作り、雛形の確認に使う。

## 保存と取り扱い

* `project.tm`には写真が含まれます。リポジトリへコミットせず、配布物にも入れません（必要な場合は撮影者全員の同意を得たうえで別途判断します）。
* スタッフ間の受け渡しは、アクセスを限定した保存場所で行います。
* アップロードしたモデル（共有リンク）には写真は含まれず、写真を復元することもできません。台本に書くのはこのリンクだけです。
* 当日に参加者を撮影したサンプルは、原則として保存せず、終了後に破棄します（スタッフ向け資料の「8. 終了後」）。

## 参加者のモデル（当日）

| 項目 | 内容 |
| --- | --- |
| 作る場所 | 参加者それぞれのPC（USBカメラ）。写真はそのPCのブラウザの中だけにある |
| クラス | `stand`（気をつけ）と`kime`（その参加者の決めポーズ）。ラベルは全員同じ |
| 枚数 | 各30〜50枚。本人だけで撮る |
| 提出 | 共有リンクだけを掲示板へ出す。`project.tm`は保存・提出しない |
| 台本 | 参加者の場面`suitor-NN`の`recognitionModel: PoseNN` |

上演は前のカメラで行うため、席での撮影とは距離・明るさ・角度が変わります。撮影時に前後へ半歩動いてもらい、ゆらぎを含めます。
